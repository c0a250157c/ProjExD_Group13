足音を敵AIにつなぐためのガイド（プレイヤー担当向け）
対象：ProjExD_Group13／第6回／敵AI統合PR #4

この資料は実装例です。下の例は、まだゲーム本体には組み込んでいません。
担当者が内容を理解し、自分の作業ブランチで実装・調整してください。

1. 最初に知っておくこと

「足音をスピーカーから鳴らすこと」と「敵へ音がしたことを知らせること」は別の処理です。
今回は、まず敵への通知を接続します。音声ファイルがなくても確認できます。

主人公担当：走って足音が発生したタイミングで、音の場所と届く距離を返す。
敵AI担当：届いた情報を受け取り、聞こえる距離の敵をSEARCHへ切り替える。

受け渡しは次のようにつながっています。

Player.update → Game.update → Game.update_guards → Guard.update

Game側とGuard側の受け渡しは、敵AI統合PR #4で接続済みです。
https://github.com/kusupon/ProjExD_Group13/pull/4

代表者がPR #4を取り込んだ後、そのmainを自分のフォーク・パソコンへ同期してください。
すでに主人公担当の変更がある場合は、そのブランチへ最新版を取り込み、両方の変更を残します。

2. 渡す情報は「音の位置」と「届く距離」だけ

contracts.pyには、すでに次の情報の入れ物があります。

    class NoiseEvent:
        position: tuple[float, float]
        radius: float

使い方の例：

    NoiseEvent(
        position=(self.position.x, self.position.y),
        radius=240.0,
    )

position：音が発生した画面上の座標。単位はピクセルです。
          マップの「何列・何行」というマス座標は渡さないでください。
radius  ：音が届く半径。単位はピクセルです。240.0はNキーと同じ仮設定です。

NoiseEventはgame.pyですでにimportされています。別の同名クラスを作る必要はありません。

3. どこを変更するか

変更場所はgame.pyのPlayerクラスです。
すでに足音や移動の処理を作っている場合は、同じタイマーを重複して追加せず、
その処理からNoiseEventを返すように接続してください。

以下は「走って実際に移動している間、約0.35秒ごとに音を通知する」実装例です。
0.35秒と240ピクセルは仮の値なので、グループで相談して調整できます。

変更A：Player.__init__の最後に、足音の間隔を測る変数を追加する。

        self.footstep_timer = 0.0

最初は0なので、走り始めにすぐ音を出せます。
Game.resetではPlayerを作り直すため、再挑戦時にはこの値も0に戻ります。

変更B：Player.updateの説明文のすぐ下、移動処理より前に追加する。

        previous_position = self.position.copy()
        self.footstep_timer = max(0.0, self.footstep_timer - dt)

previous_position：動く前の位置を保存します。
copy()：後で位置が変わっても、「動く前の位置」を残すために必要です。
dt：前回の更新から経過した秒数です。毎回、残り時間から引きます。

変更C：Player.update末尾の次の1行を、下の例に置き換える。

    置き換える行：
        return ()  # 足音は主人公担当が追加する

    置き換え後の例：
        moved = self.position.distance_squared_to(previous_position) > 0.01
        if (self.sprinting and moved and not self.hidden
                and self.footstep_timer <= 0.0):
            self.footstep_timer = 0.35
            return (
                NoiseEvent(
                    position=(self.position.x, self.position.y),
                    radius=240.0,
                ),
            )
        return ()

移動処理の後に置くことで、移動後の位置を音の発生場所として返します。
movedは「実際に位置が変わったか」です。壁に押し付けて走るだけの状態では通知しません。
self.sprintingを使うので、Shiftを押していてもスタミナ切れなら足音を出しません。
not self.hiddenは、隠れている間にこの例の足音を出さない条件です。

return ()：今回は音がない、という空のタプルを返します。
return (NoiseEvent(...),)：音が1件入ったタプルを返します。末尾のカンマが必要です。
NoiseEventをそのまま返したり、returnだけを書いてNoneを返したりしないでください。
敵側は、返された一覧を順番に読み取る仕組みです。

4. 敵側ではどう動くか

・主人公が見えている敵は、音より追跡（CHASE）を優先します。
・見えていない敵は、範囲内の音を聞くと、その位置の探索（SEARCH）を始めます。
・範囲外の音と、接触後の停止時間中に届いた音には反応しません。
・現在の音判定は距離のみで、壁越しにも聞こえます。
・音の発生場所に着いてから約3秒間探し、再発見も新しい音もなければ巡回に戻ります。
・新しい音を聞くと探索先と残り時間が更新されます。毎フレーム通知しないようにします。

隠れる操作や効果音の再生は、この例では実装しません。
実際に音を鳴らす場合は、足音の通知を出すタイミングに合わせて再生すると分かりやすくなります。

5. 動作確認の順番

まず、タイトルで1・2を選び、両ステージで確認してください。

□ 普通に歩く／止まる：この例では走行時の足音を通知しない。
□ 敵の近くで壁の陰を走る：Nキーを押さなくても敵がSEARCHになる。
□ 走るのをやめる：新しい音が止まり、敵が探索先へ到着して約3秒後にPATROLへ戻る。
□ 敵の視界内を走る：SEARCHではなくCHASEになる。
□ 敵から240ピクセルより遠くで走る：その敵は音に反応しない。
□ 壁へ向かって走り続ける：位置が変わらない間は通知しない。
□ スタミナが切れる：self.sprintingがFalseになり、走行時の通知が止まる。
□ 隠れ状態がTrue：この例の足音を通知せず、敵も主人公を視認しない。
   ※隠れる操作が未実装なら、主人公担当の実装後に確認する。
□ 一時停止・再開、再挑戦：エラーなく続けられる。

Nキーは、敵側の受信処理を試す仮の操作です。
Nキーで反応するだけでは、走行時の足音が接続できた確認にはなりません。
走って確認するときはNキーを押さずに試してください。

6. うまく動かないとき

「NoneType is not iterable」など：Player.updateのすべての経路でタプルを返しているか確認。
「NoiseEvent is not iterable」など：return (NoiseEvent(...),) のカンマを確認。
敵が違う場所へ向かう：positionにマス座標ではなくself.positionを使っているか確認。
壁に隠れても音が届く：現在の仕様どおりです。視界と音は別の判定です。
ずっと探索する：音を毎回通知していないか、走り続けて新しい音を出していないか確認。
走っても反応しない：self.sprinting、距離、音通知のreturn、敵の停止状態を確認。
